Install or update Exegete

The newest version is 0.15.1-alpha.1, from 23 October 2026.

What's new: Exegete now takes one backup before every change to a project's database, without its audio and video, and a restore's preview says what it would bring back. A file not saved as UTF-8 can be read in the character set you choose, and two settings are now switches. The full notes for 0.15.1-alpha.1 say what changes for you, in their "Upgrading" part.

Download Exegete 0.15.1-alpha.1 for Claude Desktop

The file is called exegete-0.15.1-alpha.1.mcpb. Every version before 1.0 is marked "alpha", meaning an early version.

To find out which version you have, ask Claude: "Is Exegete up to date?" Exegete answers from version 0.14.2-alpha on, except with the tool set core, which has no such tool. With Exegete's check switched off, the answer still gives the version you have, without connecting to anything.

In Claude Desktop

Updating leaves your projects and your conversations as they are.

  1. Download. Click the button above. When the download has finished, your browser shows the file in its list of downloads. Its name starts with exegete-0.15.1-alpha.1.
  2. Open it. Click the file there, or double-click it in your Downloads folder. Claude Desktop opens and shows Exegete, with the same reminder as the first time to install only extensions you trust. Click Install. If Claude Desktop says it needs to fetch a few things, click Install again. Fetching them needs the internet.
  3. Restart Claude Desktop. Quit it completely, then open it again, so that it starts the new version. Closing its window is not enough.
    • On a Mac: with Claude Desktop in front, press Cmd and Q together, or choose Quit from the app's menu at the top of the screen.
    • On Windows: at the bottom right of the screen, near the clock, find the Claude Desktop icon. You may need to click the small upward arrow first. Right-click the icon and choose Quit or Exit.
    Wait until the Claude Desktop icon has gone, then open the app again. If you are not sure it has quit, restarting the computer always works.
  4. Check. In a new conversation, ask Claude: "Is Exegete up to date?" If Claude asks whether it may use Exegete, allow it. The answer should say that you have 0.15.1-alpha.1. The assistant may need to open your project again.

If you use Exegete on more than one computer, update it on each one.

New in 0.15.1. Three tools announced as going are removed. The full notes name each one and what replaces it. A choice that Claude Desktop saved for one of them no longer applies.

Two switches replace two text boxes. The switches "Limit Exegete to its small tool set" and "I use QualCoder on this computer" replace the text boxes "Tool set" and "Do you also use QualCoder on this computer?". Both switches are off after the update, and Exegete no longer reads what was typed in the text boxes. If "Tool set" said core, switch on "Limit Exegete to its small tool set". After changing a setting, quit Claude Desktop and open it again.

Two tools have new names in 0.15.0. analyze_for_coding is now start_coding_session, and analyze_file_with_coding is now read_file_with_codings. Their earlier names keep working until Exegete 0.15.4. Claude Desktop keeps its choices for each tool by name, so a choice to let one of them run without asking, or to block it, does not carry over to the new name. You may want to look at Exegete's tools once in Claude Desktop's settings.

If something goes wrong

  • Nothing happens when I open the file, or another program opens it. Open Claude Desktop's Settings, then Extensions, then Advanced settings, click Install Extension..., and choose the file.
  • There are several Exegete files in my Downloads folder. Use the one with 0.15.1-alpha.1 in its name.
  • Claude Desktop refuses the extension. The extension is not signed by its developer, and a computer or Claude account managed by your university or employer may refuse it. The decision is your IT team's: you could send them this page and PRIVACY.md, which says what Exegete does and sends. The version you have keeps working meanwhile.
  • Exegete's tools are missing, or the old version still answers. Claude Desktop was not fully quit. Quit it as in step 3, wait, and open it again, or restart the computer.
  • Anything else. Ask on GitHub Issues, which needs a free GitHub account. Say what you did and what Claude showed, and leave out any participants' data.

Hearing about new versions

In Claude Desktop, unless you switched it off, Exegete checks whether a newer version exists at most once a week, and when you ask, and when it finds one it gives Claude a note for you, once. Nothing from your projects is sent. GitHub, which hosts this site, records your computer's internet address. To switch the check off, open Claude Desktop's Settings, Extensions, Exegete, and switch off "Tell me when a new version is out". PRIVACY.md, "Checking for new versions", says exactly what is sent. If your network blocks the check, Exegete cannot tell you, but this page always shows the newest version.

If you installed Exegete with a Terminal

This is the route of Claude Code, LM Studio, OpenAI's apps and Claude Desktop set up by hand. First quit the app that starts Exegete, such as Claude Desktop, Claude Code or LM Studio, so that nothing uses Exegete while it changes. Then take the step below for the way you installed it, in Terminal, or PowerShell on Windows, and open the app again.

On Python 3.10, these steps cannot install a version after 0.15.1-alpha.1, even when Exegete tells you that a newer one is out, because later versions need Python 3.11 or newer.

If you have switched Exegete's check on, with EXEGETE_UPDATE_CHECK=on, you can ask your assistant "How do I update Exegete?" instead. From its first check on, at least seven days after it first tells you about the check, the answer gives the step for your computer, with your folders filled in. The tool set core has no such tool.

Bringing in PDF and EPUB files needs Exegete's optional part, which the steps below do not add. INSTALL.md, "PDF and EPUB: the optional part", says how to add it and what its licence means. Without it, Exegete brings in the other documents and says when it cannot read a PDF or an EPUB.

New in 0.15.1 on these routes: the three tools above are removed, and a call that passes an argument removed with them (cascade, owner, search_memo) is refused with the name of what replaces it. Two settings, EXEGETE_SMALL_TOOLSET and EXEGETE_I_USE_QUALCODER, are switches, which take on, true or 1. With Python 3.11 to 3.14 on Windows x64, and on Linux on x86-64 and Arm, the optional part for PDF and EPUB now brings PyMuPDF 2, and the full notes say what that means on Windows.

New in 0.15.0 on these routes: the tool set full, the default, now includes creating a project. New projects go, as before, to ~/Documents/Exegete projects unless EXEGETE_WORKSPACE names another folder, and a stored lifecycle is read as full. The two renamed tools above apply here too. The full notes list the new settings, such as EXEGETE_CODER_NAME.

pip, in a virtual environment

Run the environment's own Python, for example:

"$HOME/exegete-venv/bin/python" -m pip install "exegete==0.15.1a1"

In PowerShell on Windows:

& "$HOME\exegete-venv\Scripts\python.exe" -m pip install "exegete==0.15.1a1"

pipx

pipx install --force "exegete==0.15.1a1"

uv tool

uv tool install --force "exegete==0.15.1a1"

uvx

uvx keeps running the version it fetched first until the command names another, so there is nothing to type in Terminal. In the app's entry for Exegete among its MCP servers, where the command is uvx, change exegete, with any version after an @, or qualcoder-mcp, Exegete's earlier name, to exegete@0.15.1a1. The app fetches the new version the next time it starts, which needs the internet that once.

A copy of the source (git)

Go to the copy's folder, then fetch the release and move to it, then install it again with the copy's own Python. The merge stays on your branch, and refuses if the copy has changes of its own.

cd "$HOME/Documents/exegete"
git fetch --tags
git merge --ff-only v0.15.1-alpha.1
"$HOME/Documents/exegete/venv/bin/python" -m pip install -e .

In PowerShell on Windows:

cd "$HOME\Documents\exegete"
git fetch --tags
git merge --ff-only v0.15.1-alpha.1
& "$HOME\Documents\exegete\venv\Scripts\python.exe" -m pip install -e .

Use your own folder if the copy is elsewhere.

Under the earlier name, qualcoder-mcp

In a virtual environment, update both names together, with the environment's own Python:

"$HOME/exegete-venv/bin/python" -m pip install "qualcoder-mcp==0.15.1a1" "exegete==0.15.1a1"

In PowerShell on Windows:

& "$HOME\exegete-venv\Scripts\python.exe" -m pip install "qualcoder-mcp==0.15.1a1" "exegete==0.15.1a1"

With pipx or uv tool, move to the new name first: INSTALL.md, "Coming from qualcoder-mcp", has the steps. The earlier name's last release comes with Exegete 1.0, so you may want to move to the new name before then.

If you are not sure how you installed Exegete, or none of these fits, INSTALL.md, "Updating the MCP Server", covers every way.
