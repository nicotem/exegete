Install or update Exegete

The newest version is 0.14.2-alpha, from 7 October 2026.

What's new: Exegete can now tell you when a new version is out, and it gives the assistant a brief on how to work with you. QualCoder 4.0 is now the version it is checked against. The full notes for 0.14.2-alpha.

Download Exegete 0.14.2-alpha for Claude Desktop

The file is called exegete-0.14.2-alpha.mcpb. Every version before 1.0 is marked "alpha", meaning an early version; the newest alpha is the one to use.

Not sure which version you have? Ask Claude: "Is Exegete up to date?" (Exegete 0.14.2-alpha or later; not with the tool set core, which has no such tool). With Exegete's check switched off, it still tells you the version you have, without connecting to anything.

In Claude Desktop

It takes a minute or two. Your projects stay as they are, and so do your conversations.

  1. Download. Click the button above. When it has finished, your browser shows the file in its list of downloads. Its name starts with exegete-0.14.2-alpha.
  2. Open it. Click the file there, or double-click it in your Downloads folder. Claude Desktop opens and shows Exegete, with the same reminder as the first time to install only extensions you trust. Click Install. If Claude Desktop says it needs to fetch a few things, click Install again: it takes a minute and needs the internet.
  3. Restart Claude Desktop. Quit it completely, then open it again, so that it starts the new version. Closing its window is not enough.
    • On a Mac: with Claude Desktop in front, press Cmd and Q together, or choose Quit from the app's menu at the top of the screen.
    • On Windows: at the bottom right of the screen, near the clock, find the Claude Desktop icon (you may need to click the small upward arrow first), right-click it and choose Quit (or Exit).
    Wait until the Claude Desktop icon has gone, then open the app again. If you are not sure it has quit, restarting the computer always works.
  4. Check. In a new conversation, ask Claude: "Is Exegete up to date?". If Claude asks whether it may use Exegete, allow it. It should answer that you have 0.14.2-alpha. The assistant may need to open your project again.

Use Exegete on more than one computer? Update it on each one.

Something went wrong?

  • Nothing happens when I open the file, or another program opens it. Open Claude Desktop's Settings, then Extensions, then Advanced settings, click Install Extension..., and choose the file.
  • There are several Exegete files in my Downloads folder. Use the one with 0.14.2-alpha in its name.
  • Claude Desktop refuses the extension. The extension is not signed by its developer, and a computer or Claude account managed by your university or employer may refuse it. The decision is your IT team's: you could send them this page and PRIVACY.md, which says what Exegete does and sends. The version you have keeps working meanwhile.
  • Exegete's tools are missing, or the old version still answers. Claude Desktop was not fully quit. Quit it as in step 3, wait, and open it again; or restart the computer.
  • Anything else: ask on GitHub Issues (a free GitHub account is needed). Say what you did and what Claude showed; never include participants' data.

Hearing about new versions

In Claude Desktop, unless you switched it off, Exegete checks whether a newer version exists at most once a week, and when you ask, and Claude tells you once when it finds one (if Claude passes the note on). Nothing from your projects is sent; GitHub, which hosts this site, records your computer's internet address. To switch it off: Claude Desktop's Settings, Extensions, Exegete, "Tell me when a new version is out". PRIVACY.md, "Checking for new versions", says exactly what is sent. If your network blocks the check, Exegete cannot tell you; this page always shows the newest version.

If you installed Exegete with a Terminal

This is the route of Claude Code, LM Studio, OpenAI's apps and Claude Desktop set up by hand. In every case, first quit the app that starts Exegete (for example Claude Desktop, Claude Code or LM Studio), so that nothing is using it while it changes; then take the step for the way you installed it, in Terminal (PowerShell on Windows); then open the app again.

If you have switched Exegete's check on (EXEGETE_UPDATE_CHECK=on), you can ask your assistant "How do I update Exegete?" instead: from its first check on, at least seven days after it first tells you about the check, the answer gives the step for your computer, with your folders filled in. (Not in the tool set core, which has no such tool.)

pip, in a virtual environment

Run the environment's own Python, for example:

"$HOME/exegete-venv/bin/python" -m pip install "exegete==0.14.2a0"

In PowerShell on Windows:

& "$HOME\exegete-venv\Scripts\python.exe" -m pip install "exegete==0.14.2a0"

pipx

pipx install --force "exegete==0.14.2a0"

uv tool

uv tool install --force "exegete==0.14.2a0"

uvx

uvx keeps running the version it fetched first until the command names another, so there is nothing to type in Terminal. In the app's settings for Exegete (its entry for MCP servers), where the command is uvx, change exegete (with any version after an @), or qualcoder-mcp, Exegete's earlier name, to exegete@0.14.2a0. The app fetches the new version the next time it starts, which needs the internet that once.

A copy of the source (git)

Go to the copy's folder, then fetch the release and move to it (this stays on your branch, and refuses if the copy has changes of its own), then install it again with the copy's own Python:

cd "$HOME/Documents/exegete"
git fetch --tags
git merge --ff-only v0.14.2-alpha
"$HOME/Documents/exegete/venv/bin/python" -m pip install -e .

In PowerShell on Windows:

cd "$HOME\Documents\exegete"
git fetch --tags
git merge --ff-only v0.14.2-alpha
& "$HOME\Documents\exegete\venv\Scripts\python.exe" -m pip install -e .

Use your own folder if the copy is elsewhere.

Under the earlier name, qualcoder-mcp

In a virtual environment, update both names together, with the environment's own Python:

"$HOME/exegete-venv/bin/python" -m pip install "qualcoder-mcp==0.14.2a0" "exegete==0.14.2a0"

In PowerShell on Windows:

& "$HOME\exegete-venv\Scripts\python.exe" -m pip install "qualcoder-mcp==0.14.2a0" "exegete==0.14.2a0"

With pipx or uv tool, move to the new name first: INSTALL.md, "Coming from qualcoder-mcp", has the steps. The earlier name's last release comes with Exegete 1.0, so moving to the new name before then is worth doing.

Not sure which way you installed it, or none of these fits? INSTALL.md, "Updating the MCP Server", covers every way.
